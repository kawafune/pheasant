# Pheasant SEOルール（SEO_Master_Logic v2.8 からの抜粋）

最終同期：2026-10-11（SEO_Master_Logic v2.8） ／ 正本：Notion「SEO_Master_Logic」（このファイルは写し。食い違ったら正本を優先し、このファイルを更新する）

## 0. 最優先の方針（Happiino）
- 記事は、まず読んだ人の**感情が変わること・学びになること**を第一にする。そのうえで**行動に移せる**ところまで導く。
- キーワードや見出しの型は、この目的を検索で届けるための手段として使う。型のために読みやすさを犠牲にしない。

## 1. 設計（記事を書く前に決めること）
記事ごとに次の7項目を入力として受け取る（不足があれば出力の冒頭で【要確認】として指摘する）。
1. 検索意図（属性ラベル付き。例：購入直前／比較検討／来店前／旅の計画／信頼づくり）
2. 記事タイトル案
3. フォーカスKW（同じ検索意図のKWを最大8個程度。1つ目がメインKW）
4. 結論付けとスタンス（2文程度：「○○ではなく××で判断すべき」＋「こういう人はこうすると後悔しない」）
5. 読後の変化（1行：「読む前の気持ち → 読んだ後の気持ち・学び → 次の行動」）
6. キャッシュポイント／送客先（事業ごとの定義は §6）
7. 既存記事URL（あれば。食い合い確認用）

## 2. 見出しとキーワード
- H1（記事タイトル）は1つ。**28〜40字前後**。メインKWを自然に含め、内容が一目で分かり、本文と一致すること。煽り・釣りは禁止。
- H2は**2つ**が基本。H2にはメインKWを**自然な形で**入れる。
- H3は**12個程度**が目安（固定ではない。検索意図に必要な分だけ）。見出し用KW（サジェスト・関連KW）は主にH3で使う。
- **全てのH3にメインKWを入れない**（不自然になる）。
- 最後のまとめ見出しにはメインKWを自然に入れる。
- KWは**できるだけ原形を残す**が、**完全一致にはこだわらない**。KWを入れることより、読者が違和感なく読めることを優先する。KWのために日本語を崩さない。
- 見出しは短く、読者の「質問」の形にすると良い（目次だけで読む場所を選べる）。
- メタディスクリプション：記事を自然に要約した1〜2文。メインKWは自然に1回でよい。記事ごとに固有の文にする。
- 同じ質問になるKWは1つの見出しにまとめる。

## 3. 記事の構成
タイトル → （広告を含む場合）PR表記 → アイキャッチ → イントロダクション → 記事のポイント4つ → 目次 → H2＋導入文＋H3群 → H2＋導入文＋H3群 → まとめ

- **イントロダクション**：読者の悩みに共感 → 結論・方向性を早めに示す → この記事で分かること。メインKWと主要な見出し用KWを自然に含める。長くしすぎない。
- **記事のポイント4つ**：これだけ読めば結論が分かるようにする。
- **各見出しの直後1〜2文で、その見出しの答えを先に書く**（詳細はその後）。拾い読みできる構造にし、AIが引用しやすくする。
- 本文の型：主張 → 理由 → 具体例 →（必要なら）迷いや反論への理解 → もう一度主張。
- 比較・手順・料金などは文章より表や箇条書き。
- スマホで読みやすく：1文を長くしない。2〜3文ごとに段落を分ける。太字・マーカーは最小限。
- **まとめ**：見出しのコピペにしない。「読後の変化」に沿って、次の行動を**一つだけ**、押し売りせずに提案する。

## 4. 一次情報と事実（最重要の禁止事項）
- 入力された参考データ（一次情報）を最優先の根拠にする。データにない固有名詞・数字・料金・営業時間を作らない。
- **使っていないもの・行っていない場所を、使った・行ったように書かない。参考データの他人の体験を、書き手自身の体験のように書かない。** 体験を書くのは、参考データに「運営者の体験」と明記されているものだけ。
- 参考データ内の一次情報（取材メモ、職人の言葉、現地で困ったこと、事前に知りたかったこと等）を、少なくとも1つのH3として必ず生かす。
- 価格・キャンペーン・営業情報・仕様・解約条件など、読者が損をしうる情報は【要確認】を付けて出力する。
- 引用は出典名とリンクを明記し、自分の解説を主にする。公的機関などの資料は、信頼の裏づけとして出典リンク付きで使ってよい。

## 5. 表現の禁止（YMYLに近い商品）
- 健康・病気・効果を断定しない。NG：「治る」「防げる」「完全に除去」「必ず効果がある」「医学的に証明」「健康に効果」「改善する」「予防」。
- 使ってよい形：「〜をサポートする機能」「（自社）試験では〜という結果」「使う環境で感じ方は変わります」「健康効果を保証するものではありません」。公開している試験結果を超える効果は書かない。
- 記事の中心は「商品選びの判断材料」（素材・着心地・サイズ・手入れ・価格・口コミ）に置く。

## 6. 事業ごとの設定（mediaType）

### tabinoto（タビノト。）
- 目的：宣伝が苦手な職人や、知られていない場所に光を当て、「知ってもらえる可能性」を増やす。
- 収益：記事広告・純広告・掲載料（自治体・観光協会・産地の組合・地域事業者も対象）。アドセンス・アフィリエイトは補助。
- 価値の測り方：**取材対象への送客（外部リンクのクリック）**と、AIに要約できない一次情報の量と質。
- 送客先（§1-6）：取材先の公式サイト・予約・通販・地図。**記事の終わりに必ず置く**。
- 優先する検索語：場所・人・体験。知識系（〜とは、意味、海外の反応）は新規では作らない。
- 長さ：解説記事は1万字前後まで可。その場合 §3 の拾い読み構造を必須にする。
- 古くなる情報（営業時間・料金・行事日程）は更新日を表示し、【要確認】を付ける。
- 大手と網羅性で競わない。「人気スポット10選」より「実際に行って静かだと感じた3か所」。
- 広告記事の場合はPR表記を必ず入れる。

### sumigi（炭の繊維のアパレル）
- 送客先：自社ショップ（shop.sumi-gi.com）の該当商品、または開発ストーリー。
- リンクの置き場（押し売りにならない範囲で）：①イントロの結論のすぐ後 ②最初のH2の結論部分 ③まとめの最後。
- §5 の表現ルールを最も厳しく適用する（炭の消臭・抗菌・調湿など）。
- 強い入口：お悩み解決系（服 チクチク／汗 臭い 服 など）、「長く着る服」の考え方。
- 長さ：必要な分だけ。無理に伸ばさない。

### cocci（高円寺の雑貨カフェ）※画面上の値は `cocci3`
- 送客先：来店・予約・空間レンタルの問い合わせ。
- KWは2種類：地域名あり（今すぐ来る人。例：高円寺 カフェ 一人）／地域名なし（いつか来る人。例：スープ 作り置き コツ）。
- 長さ：必要な分だけ。店舗情報は短く正確に。

### default
- §0〜§5 のみ適用。

## 7. 出力の自己点検（出力前に必ず確認）
- [ ] H1は28〜40字前後で、メインKWが自然に入っているか
- [ ] H2にメインKWが自然に入っているか／全H3に入れすぎていないか
- [ ] 各見出しの直後に答えがあるか
- [ ] 参考データにない事実・体験を作っていないか
- [ ] §5 のNG表現がないか
- [ ] まとめが「読後の変化」に沿った次の行動を一つ示しているか
- [ ] 送客先（または購入先）へのリンク位置が指定されているか
- [ ] 価格・営業時間・仕様など、読者が損をしうる情報に【要確認】が付いているか
